# Live smoke run, 2026-11-07

How this was made: `npm run smoke -- --local --redact` (PLAN.md §13.5), with the proxy running locally
through `wrangler dev`. It is **not** a run against a deployed proxy, because nothing is deployed yet:
the Cloudflare account and the GitHub repository belong to the owner. Re-run it with
`npm run smoke -- --proxy <deployed proxy>` after the first deploy (the `Smoke` workflow does this weekly).

What it does: for each outlet it takes the newest item of the outlet's own feed, so the corpus never
goes stale, and runs the real pipeline on it (the extractor runs in Node with jsdom), then checks that the
image and logo candidates really load through the proxy. It asks each page once, with the proxy's honest
`User-Agent`. The Economist, the New York Times and the Financial Times are known to block automated
readers and were not asked; for them the app offers the bookmarklet, pasted source and manual entry.

This copy is redacted: headlines and article addresses are left out.

Things to know when reading it:

- A first attempt at a 2.2 second pace tripped the proxy's rate limiter on four outlets (DER SPIEGEL,
  TechCrunch, The Verge, Wired), each of which needs a feed request and an article request. The smoke
  script now waits three seconds between page requests. The table below is the run at that pace.
- TechCrunch's icon candidate does not load through the proxy; the card falls back to the next logo
  candidate or the outlet name.
- Corriere della Sera's feed currently lists an old article (2024) as its newest item; its date is what
  the page says.
- "Result: ok" means a title, a site name, a date and an image that loads were found. It does not mean they
  are right, so the table has been read by eye: the sites and dates match the outlets.
